# Optific+ trial

A shared workspace for an optician group: **Chat + BI**, an **org Map**, a **Brain**, and a
**Today** view. Next.js (App Router) + TypeScript + Tailwind + shadcn/ui.

The rule the whole thing is built around: **the LLM never computes numbers.** Every figure comes
from pure functions in `src/data/*`, and the model may only quote what those functions return.

## Setup

```bash
npm install
npm run seed        # writes data/*.csv (deterministic, seeded)
npm run dev         # http://localhost:3000
```

### LLM configuration (server-only)

Create `.env.local` (git-ignored) from `.env.example`:

```
LLM_BASE_URL=https://opencode.ai/zen/go/v1
LLM_API_KEY=<your key>
MODEL_NAME=deepseek-v4.1-flash
LLM_SESSION=opticf-trial
```

- The endpoint is any **OpenAI-compatible chat-completions** API, using OpenAI style function
  calling. Swapping provider (for example to the DeepSeek API directly) is an env change only:
  set `LLM_BASE_URL=https://api.deepseek.com/v1`, `MODEL_NAME=deepseek-chat`, and leave
  `LLM_SESSION` blank. Nothing else in the code is provider specific.
- `LLM_SESSION` is optional. It is only needed by endpoints that require a routing session
  header (`x-opencode-session`, which is what OpenCode Go uses). It is not a secret.
- The key is read only from the environment. It is never printed, logged or committed.

Check connectivity and tool calling before running the chat tests:

```bash
npm run llm:check    # GET /models (status + model ids only) then one dummy tool call
npm run chat:test    # real endpoint, prints tool calls, widgets, text, mapHighlight and timing
npm run chat:test -- --mock   # same harness with a deterministic mock transport (no key)
```

## Deploying to Vercel

1. Push the repository to GitHub.
2. In Vercel, "Add New Project" and import the repository. Framework preset: Next.js (defaults).
3. Add the environment variables in **Project Settings > Environment Variables** (Production and
   Preview):
   - `LLM_BASE_URL`
   - `LLM_API_KEY`
   - `MODEL_NAME`
   - `LLM_SESSION` (optional, only for OpenCode Go)
4. Deploy.

Notes:

- The generated CSVs must ship inside the serverless bundle. This is handled in `next.config.ts`
   with `outputFileTracingIncludes: { '/': ['./data/**/*.csv'], '/api/chat': ['./data/**/*.csv'] }`.
- The CSVs are generated by `npm run seed`. They are git-ignored, so either commit them or run the
  seed as part of the build. To commit them, remove the `data/*.csv` line from `.gitignore`.
- After deploy, check `POST /api/chat` (or the Chat tab) and confirm the LLM env vars are set.

## Themes

Light and dark are driven by CSS variables in `src/app/globals.css` (the shadcn
pattern, oklch), switched with `next-themes` (system default, manual toggle in the
top bar, persisted, no flash on load).

- Light: warm cream canvas, navy ink, coral accent.
- Dark: neutral surfaces on a near-black base, using the shadcn dark neutrals:
  `card` and `popover` are `oklch(0.205 0 0)`, and `secondary`, `muted` and
  `accent` are `oklch(0.269 0 0)`, on a `oklch(0.145 0 0)` background. The coral
  accent is kept in both modes.

Every colour is stored as a bare oklch triple and referenced as
`oklch(var(--token) / <alpha-value>)` in `tailwind.config.ts`, so opacity
modifiers like `bg-card/80` keep working. Charts read `--chart-1` to `--chart-5`,
so they follow the theme automatically.

## Charts

Chat and BI charts render with **Dither Kit** (`src/components/dither-kit/`, installed from the
`tripwire.sh` registry via the shadcn CLI; it brings `d3-scale`, `d3-shape` and `motion`).

- Series colours are the Dither Kit palette, plus one local addition: `brand` (`[210, 94, 40]`,
  `#D25E28` burnt orange), the send button colour supplied from the brand reference. It is a local
  edit to `palette.ts`, so keep it in mind when running `dither-kit update`. To change the button
  colour, change that one entry.
- `variant="solid"` with `bloom="aura"` gives the dithered fill and glow. Note that Dither Kit's
  `gradient` variant is deliberately sparse at rest and only densifies on hover, which reads as a
  pale wash on a button.
- The axis and the tooltip quote the **server's pre-formatted strings** through `tickFormatter` and
  `valueFormatter`, so a chart can never show a number the rest of the product disagrees with.
- To use the brand coral instead of Dither Kit orange, add a `coral` entry to
  `src/components/dither-kit/palette.ts` (`fill: [220, 124, 99]`) and set it in the widget's colour list.

Note: Dither Kit paints its bars on animation frames, so charts only appear in a visible tab. The map
has a hidden-tab fallback; Dither Kit does not.

## Architecture

```
src/
  domain/types.ts     Data model (Practice, MonthlyPerformance, TrainingRecord, Dataset)
  lib/                csv, prng, months, format (all pure)
  data/               THE data layer, all numbers originate here
    metrics.ts          query_metrics()
    compare.ts          compare()
    training.ts         training_status()
    attention.ts        rank_attention()
    today.ts            today_priorities()  -> the Today tab
  ai/                 Chat layer (server)
    llm.ts              OpenAI-compatible transport behind an interface
    tools.ts            tools wrapping the pure functions, each returns widgets
    chat.ts             tool loop, context and follow-ups, number guard
    system-prompt.ts    the rules (tools for every number, never invent causes)
    guard.ts            verifies every number in the answer came from a tool
  app/                Next.js routes
    page.tsx            the workspace shell
    api/chat/route.ts   POST /api/chat
  components/         UI (shadcn), ui/ generated by the shadcn CLI
```

### Chat API

`POST /api/chat` returns a **newline-delimited JSON stream**:

```
{ "type": "delta",   "text": "..." }        prose, streamed as it is written
{ "type": "tool",    "name": "compare" }    a tool ran
{ "type": "widgets", "widgets": [...] }     the widget list grew
{ "type": "done",    "text", "widgets", "mapHighlight", "context", "sources", "flagged" }
{ "type": "error",   "message", "status" }
```

Tools return widgets directly (`kpi | chart | table`). The server collects them and the model only
writes prose. Follow-ups work by the client echoing the previous `context` back, which the server
injects into the system prompt and uses to restrict the offered tools so refinements do not re-run
discovery.

Hardening:

- `messages` and `context` are validated before anything reaches the model. Context fields are
  whitelisted against the dataset: unknown regions and practice ids are dropped, `metric` must be a
  single token, `group_by` must be one of three values, and `period.month` must be `YYYY-MM`.
- Every LLM call has a hard timeout (`LLM_TIMEOUT_MS`, default 45000 ms). The client can abort with
  the Stop button.
- If the model uses a number that no tool returned, the server retries once, sets `flagged: true`,
  and the UI shows a warning on that answer.
- Each answer carries `sources`, rendered as chips under the reply.
